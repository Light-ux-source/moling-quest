## 2. 架构与关键决策

| 决策 | 实现 |
| --- | --- |
| 登录 | 小程序 `Taro.login()` 拿 code → 后端 `GET https://api.weixin.qq.com/sns/jscode2session`（`grant_type=authorization_code`）→ openid；首次自动建号 |
| 令牌 | 32 字节随机 token，服务端只存 SHA-256；`Authorization: Bearer`；默认 30 天；退出/注销即撤销 |
| 体验登录 | `POST /auth/dev`，仅 `ENV != production` 且 `DEV_LOGIN_ENABLED=true`；H5/本地验收使用 |
| 游客试用 | `guest_trials.client_id` 唯一，累计 1 组；登录后试用不占每日额度 |
| 每日额度 | 登录用户 3 组/日（Asia/Shanghai 00:00 重置）；失败重试不重复扣；整组失败返还；VIP 10 组/日仅预留 |
| 数据归属 | `sessions/chapters` 增加 `user_id`；游客按 `client_id` 且 `user_id IS NULL`；登录时把本机未归属数据 claim 到账号 |
| 越权防护 | 会话/报告/结算/章节全部校验归属；不属于当前用户统一返回 404，避免枚举 |
| 积分 | 直接复用现有 `exp`，个人中心/记录/结算文案统一“积分”，不新增货币 |
| 学习记录 | `GET /records` 仅列表（分页 20），不提供历史报告详情入口 |
| 注销 | 删除昵称/头像/openid 绑定，撤销令牌；学习记录匿名化（`user_id=NULL`，`client_id=deleted_<id>`）保留统计 |
| 头像 | 微信 `chooseAvatar` 或 H5 `chooseImage` → 上传 `/profile/avatar`；JPG/PNG/WebP ≤2MB；存 `backend/data/uploads/avatars/`，经 `/media/avatars/*` 访问 |
| 密码 | 不做手机号/邮箱/密码注册；首次微信登录即注册 |

## 3. MySQL 数据模型（新增/变更）

> 完整字段见 `backend/app/db.py` 与 10 文档；这里只列与用户系统相关的表/列。

### 3.1 新增表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | `id`, `openid`, `unionid`, `dev_key`, `nickname`, `avatar_url`, `status`, `deleted_at` | 一个微信 openid = 一个账号；体验账号用 `dev_key` |
| `auth_tokens` | `id`, `user_id`, `token_hash`, `expires_at`, `revoked_at`, `last_used_at` | 只存哈希，不存明文 token |
| `user_settings` | `user_id` PK, `reminder_enabled` | 本期只存提醒偏好 |
| `guest_trials` | `client_id` PK, `session_id`, `ip_hash`, `used_at`, `claimed_user_id` | 游客 1 组试用与防重复 |

### 3.2 既有表变更

| 表 | 新增列 | 用途 |
| --- | --- | --- |
| `sessions` | `user_id`, `guest_trial`, `quota_refunded` | 归属、试用标记、失败返还 |
| `chapters` | `user_id` | 章节归属 |
| `questions` | `origin_question_id` | 为后续错题重练预留（本期未启用） |

### 3.3 迁移方式

- `db.init_db()` 启动时执行 `CREATE TABLE IF NOT EXISTS`，并对旧 MySQL 表做“只加列/索引”的 `_migrate`。
- 本地开发用独立实例：`backend/scripts/start_mysql_dev.sh`（端口 3307，不碰系统 3306）。
- 生产：由 DBA 创建 `utf8mb4` 库与最小权限账号，配置 `MYSQL_*`；不需要也不应该使用开发脚本。
- 旧 SQLite 文件不再被读取；如需保留历史演示数据，可重新跑 `miniapp/scripts/seed_demo.py` 或另行做一次性迁移。

## 4. 接口清单（本期新增/变更）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/wechat` | 微信 code → 登录/自动注册；返回 token + user + 迁移数 |
| POST | `/api/v1/auth/dev` | 开发体验登录（生产禁用） |
| GET | `/api/v1/auth/me` | 当前登录态；无 token 返回 `authenticated=false` |
| POST | `/api/v1/auth/logout` | 撤销当前 token |
| GET | `/api/v1/profile` | 个人中心；游客/登录双态，含积分、额度、设置 |
| PATCH | `/api/v1/profile` | 修改昵称/头像地址 |
| POST | `/api/v1/profile/avatar` | 上传头像（multipart） |
| GET/PATCH | `/api/v1/profile/settings` | 学习提醒偏好 |
| DELETE | `/api/v1/profile` | 注销账号（204） |
| GET | `/api/v1/records?limit=20&offset=0` | 学习记录列表（仅列表） |
| GET | `/api/v1/health` | 增加 `database/auth/wechat_login/dev_login` |

**既有接口变化**：

- `POST /sessions`：增加登录态/游客试用/每日额度；超限 429；重试/重新生成不重复扣。
- `GET /sessions/{id}`、`/report`、`/settlement`、`/chapters/{id}`：增加归属校验，越权 404。
- `GET /sessions`、`/chapters`、`/profile`：按登录用户或游客设备过滤。
- `PATCH /sessions/{id}/progress`、提交答案、章末综合、失败重试：增加归属校验与配额处理。

## 7. 本地运行

```bash
# 1) 启动独立开发 MySQL（端口 3307；不碰系统 3306）
cd backend
./scripts/start_mysql_dev.sh
cp .env.example .env          # 填 MYSQL_* / WECHAT_*；可留空 DEEPSEEK key 走 Mock

# 2) 后端
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000

# 3) 前端
cd ../miniapp
HOME=$PWD/.home npm run build:weapp
HOME=$PWD/.home npm run build:h5
python3 scripts/serve_h5.py dist-h5 10087

# 4) 测试
cd ../backend && .venv/bin/python -m pytest -q
cd ../miniapp && npx tsc --noEmit && node scripts/e2e.js
```

**微信登录**：`backend/.env` 的 `WECHAT_APP_ID` / `WECHAT_APP_SECRET` 已填写，重启后 `/health` 的 `wechat_login=true`。真实 `wx.login` code 仍需在开发者工具/真机走查；开发/验收也可用“体验登录”。不要在前端或仓库保存 AppSecret。

3. **VIP**：10 组/日仅预留，未开放购买/兑换。
4. **游客试用可被清缓存绕过**：已按设备 + IP 记录兜底，但不能完全防止换设备；登录用户按账号。
5. **配额并发**：当前为“先查后建”，极端并发可能多放行 1 组；后续可用事务/额度流水收敛。
6. **学习记录**：仅列表，无历史报告详情入口；报告详情仍从结算页进入。
7. **S09–S13**：未实现；`questions.origin_question_id` 已为后续错题重练预留。
8. **旧 SQLite 数据**：不自动迁移到 MySQL；演示数据可用 seed 脚本重建。
9. **微信头像/昵称**：需用户主动选择/填写，不能静默读取；可跳过并使用默认“旅人”+墨团。
10. **内容安全**：昵称/头像依赖微信组件侧安全检测；服务端 `msgSecCheck` 仍属上线前事项。

## 9. 本轮修复记录（2026-11-10）

### 9.1 问题

测试中发现：完成一组后误点“再练一组/重新生成”会被额外扣额度；额度用尽后从结算/报告/章末综合再次生成时只弹 toast，且结算页返回会反复压入章节地图，最终页面栈达到微信 10 层上限，用户只能重启小程序回首页。另有微信登录 503 时登录弹层缺少逃生出口。

### 9.2 修复

| 项 | 处理 |
| --- | --- |
| 预览页“重新生成” | 新增 `POST /sessions/{id}/regenerate`：只允许 `ready`，复用原 session/chapter，清空题目/答案/报告后原位重生成，**不额外扣额度**；`/retry` 仍只处理 `failed` |
| 登录用户额度用尽 | 统一弹“今日额度已用完，明天 00:00 恢复”，提供 **回首页**；游客仍打开登录弹层 |
| 登录态失效/微信登录失败 | 401 打开登录弹层；登录弹层增加“先回首页看看”，503/502 错误不再形成死路 |
| 页面栈 | `PageHeader` 无上一页时回首页；结算页返回改为 `navigateBack`；report/map 跳转优先复用栈内页面，避免 10 层溢出 |
| 误触/连点 | “再练一组/重练本关”增加消耗额度二次确认；创建/重生成按钮增加同步 ref 锁 |
| 错误信息 | FastAPI 422 的数组 `detail` 解析为中文可读提示，不再显示 `[object Object]` |
| 配置 | `.env` 改为按 `backend/` 绝对路径加载，启动日志输出 `wechat_login/dev_login` 状态（不打印密钥） |
