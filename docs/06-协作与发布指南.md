## 1. 分支与提交

| 项 | 规则 |
| --- | --- |
| 主干 | `main` 始终可运行、可构建 |
| 功能分支 | `feat/<scope>-<short>`，如 `feat/ui-tokens` |
| 修复分支 | `fix/<scope>-<short>` |
| 合并 | 小 PR（< 400 行）；合并前跑通质量门禁 |
| 提交格式 | Conventional Commits：`feat(quiz): 支持多选题部分分` |
| 提交粒度 | 一个可独立解释的变更；不把格式化与功能混在一起 |

**提交类型**：`feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `perf`。

## 2. 质量门禁

```bash
# 后端
cd backend && .venv/bin/python -m pytest -q

# 前端类型与构建
cd miniapp && npx tsc --noEmit && npm run build:weapp && npm run build:h5

# 端到端（H5，Mock 即可）
python3 scripts/serve_h5.py dist-h5 10087 &
node scripts/e2e.js
```

| 门禁 | 必须 | 说明 |
| --- | --- | --- |
| pytest | 是 | 新增接口/判分逻辑必须有用例 |
| tsc | 是 | 不允许类型错误合入 |
| 双端构建 | 是 | 构建失败即阻断 |
| E2E | 发布前 | 主流程必须通过 |
| 文档同步 | 是 | 行为变化需更新 `docs/03` 或 `docs/05` |
| 密钥扫描 | 是 | 不提交 `.env`、Key、真实 AppID |

## 3. 发布流程

1. 更新 `CHANGELOG.md` 的 `[Unreleased]` → 新版本号。
2. 回归：pytest + 双端构建 + E2E + 真机关键页。
3. 打 tag：`git tag -a v0.2.0 -m "..." && git push --tags`。
4. 小程序：开发者工具上传体验版 → 真机验收 → 提交审核 → 发布。
5. 后端：构建镜像 → 灰度 10% → 观察 30 分钟 → 全量；保留上一版镜像。
6. 发布后 24 小时：看错误率、生成成功率、P90、成本。

**版本号**：`0.x` 阶段以"能否完赛"为界；`1.0` 表示上线并可收费。

## 4. 环境与密钥

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| local | 开发、Mock | 本地 SQLite |
| staging | 内测、真实模型 | 独立库，可清空 |
| prod | 线上 | 备份 + 监控 |

- `backend/.env` 只存本地，已 gitignore；服务器用环境变量注入。
- 小程序端**永远不出现**模型 Key；所有 AI 调用走后端。
- 泄露处置：立即吊销 → 换 Key → 查账单 → 记录到 `docs/05`。

## 5. 文档维护

| 文档 | 何时更新 | 谁确认 |
| --- | --- | --- |
| `01-需求规格` | 范围/优先级/验收变化 | 产品 |
| `02-UI设计规范` | 颜色/组件/动效变化 | 设计 |
| `03-页面设计说明` | 页面结构/状态/文案变化 | 设计 + 前端 |
| `04-ADR` | 任何不可逆或高成本决策 | 技术负责人 |
| `05-测试报告` | 每次发布/重大修复 | 开发 |
| `06-协作指南` | 流程变化 | 全体 |
| `方案设计文档` | 架构/接口/数据模型变化 | 后端 |

**规则**：文档与代码同 PR 提交；过期内容不删除，标注"已废弃 + 替代文档 + 日期"。

## 6. Issue 与标签建议

| 标签 | 用途 |
| --- | --- |
| `type/feature` `type/bug` `type/docs` `type/design` | 类型 |
| `area/backend` `area/miniapp` `area/ui` `area/ai` | 模块 |
| `priority/P0` `priority/P1` `priority/P2` | 优先级 |
| `blocked` `needs-review` | 状态 |

**Bug 模板**：环境 / 复现步骤 / 期望 / 实际 / 截图或日志 / 影响范围。

## 7. CI 建议（GitHub Actions）

```yaml
name: ci
on:
  push:
    branches: [main]
  pull_request:

jobs:
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r backend/requirements.txt
      - run: cd backend && python -m pytest -q

  miniapp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: npm, cache-dependency-path: miniapp/package-lock.json }
      - run: cd miniapp && npm ci && npx tsc --noEmit && npm run build:weapp && npm run build:h5
```

> 未提交到仓库，避免在未确认 CI 成本/权限前自动跑；确认后可直接放入 `.github/workflows/ci.yml`。
