## 0. 结论摘要（TL;DR）

### 0.1 这次要解决什么

现有产品已经能「输入知识点 → AI 出题 → 答题 → 报告」，但用户数据只按**设备匿名 ID** 隔离，换设备就丢、无法知道“这是谁”、无法做额度与长期学习记录。本次要把匿名设备升级为**真实用户账号**：

1. 用户用**微信一键登录**，首次登录自动注册，之后同一微信始终是同一账号。
2. 登录后可读取/设置**昵称与头像**，形成可识别的个人身份。
3. 新增**个人中心（S11）**：身份、通关/星星/连续天、积分、AI 造关额度、学习记录入口、设置与免责声明。
4. 新增**学习记录列表**：按时间查看自己的闯关历史与本次积分。
5. 新增**配额规则**：游客试用 1 组；登录普通用户 3 组/日；VIP 10 组/日本期只预留、不开放；重试/重新生成不重复扣。
6. 补齐**设置、隐私同意、退出登录、注销账号**等账号生命周期能力。

### 0.2 本期明确不做

- S09 错题本、S10 成就与段位页、S12 分享卡片、S13 排行榜。
- VIP 开通、支付、订阅、兑换码。
- 手机号/邮箱/密码注册，手机号绑定。
- 好友关系链、微信通讯录、真实姓名/身份证信息。
- 多轮对话、指定信息源、内容审核的完整工程化（仅保留昵称/头像的基础校验要求）。
- 生产环境 H5 的独立登录体系（H5 仅用于开发验收与体验登录）。

### 0.3 最重要的三个变化

| 变化 | 原状态 | 新要求 |
| --- | --- | --- |
| 身份 | 匿名设备 ID，换设备不同步 | 微信账号；首次登录自动注册；跨设备同步 |
| 造关门槛 | 不登录也能无限造关（仅 IP 限流） | 游客累计试用 1 组；之后必须登录；登录用户 3 组/日 |
| 个人页 | S11 未实现，tabbar“我的”置灰 | S11 个人中心 + 学习记录列表 + 设置/隐私/注销 |

## 1. 背景与问题定义

### 1.1 现状

| 维度 | 现状 | 带来的问题 |
| --- | --- | --- |
| 身份 | 前端生成 `client_id`，服务端按设备隔离章节/统计 | 换手机、清缓存、换微信后记录丢失；无法知道用户是谁 |
| 登录 | 无登录 | 无法做账号级额度、跨端同步、账号注销与合规 |
| 个人中心 | S11 未实现；“我的”tab 置灰 | 用户看不到自己的累计成果，也找不到记录/设置入口 |
| 积分 | 已有“经验值/叶子”，但只在首页/结算局部出现 | 用户无法在一个地方看到“我总共积累了多少” |
| 配额 | 仅有展示用的月度额度，未强制拦截 | 成本不可控，也无法区分游客/登录用户 |
| 合规 | 无隐私同意、无账号注销 | 上线审核与个人信息保护存在缺口 |

### 1.2 用户真正要什么

| 表层诉求 | 真实问题 | 本次回答 |
| --- | --- | --- |
| “我要登录/注册” | 我在不同设备上想继续学，不想每次从零开始 | 微信一键登录；首次即注册；账号级记录同步 |
| “知道对应哪个微信” | 平台要知道数据属于谁，用户不想再记一套账号密码 | 用微信唯一标识绑定账号；不收集手机号/密码 |
| “读取昵称头像” | 我希望个人页看起来是“我”，而不是一个匿名设备 | 微信头像/昵称授权 + 可跳过默认身份 + 可编辑 |
| “看学习记录和积分” | 我坚持学了多久、得了多少分，需要有沉淀 | 学习记录列表 + 累计积分 + 连续天数 |
| “别让我无限制白嫖/也别一上来就逼我登录” | 产品要控成本，用户要低门槛体验 | 游客可试用 1 组，之后登录；登录后 3 组/日 |

### 1.3 产品原则

1. **先体验，后登录**：浏览不拦截；首次造关给 1 组试用；试用结束再要求登录。
2. **登录不丢数据**：登录时把本机游客记录迁移到账号，不能出现“登录后记录没了”。
3. **身份可识别但不越界**：只拿微信 openid、昵称、头像；不拿手机号、通讯录、好友列表、真实姓名。
4. **额度透明**：用户随时能看到“今天还能造几组”，超限说清楚何时恢复，不用“失败”羞辱用户。
5. **文案统一**：面向用户的“经验”统一叫“积分”；段位仍按积分计算。

## 2. 用户角色与权限矩阵

| 角色 | 定义 | 能否浏览 | 能否造关 | 额度 | 能否看学习记录 | 能否设置资料 |
| --- | --- | --- | --- | --- | --- | --- |
| 游客 | 未登录，使用本机匿名身份 | 可以（首页/章节/已有报告） | 仅可试用 1 组 | 累计 1 组 | 仅本机游客记录 | 仅默认身份，不能改 |
| 登录用户（普通） | 微信登录，非 VIP | 可以 | 可以 | 3 组/日 | 账号下全部记录 | 可以 |
| VIP（本期不开放） | 预留角色 | 可以 | 可以 | 10 组/日（预留） | 账号下全部记录 | 可以 |
| 运营/管理员 | 未来后台角色 | — | — | — | — | 本期不做后台 |

**权限边界**

- 一个微信身份 = 一个账号；同一微信在不同设备登录看到同一份数据。
- 不同微信 = 不同账号；互相看不到对方的学习记录、积分、配额。
- 游客退出/清除缓存后，本机游客身份可能变化；游客记录不作为长期承诺。
- 本期不提供“切换账号后合并两个微信账号”的能力。

## 3. 核心用户旅程

### 3.1 新用户：游客试用 → 登录 → 迁移

```
打开小程序
  → 首页浏览（不强制登录）
  → 输入知识点 / 选难度题量题型
  → 点「生成关卡」
  → 游客身份允许：这是第 1 组试用
  → 生成中 → 预览 → 答题 → 结算/报告
  → 再点「生成关卡」
  → 提示「试用已用完，登录后可继续」
  → 微信一键登录（首次即注册）
  → 本机游客记录自动迁移到账号
  → 回到刚才的输入，继续生成（不丢主题/难度/题型）
```

### 3.2 老用户：登录 → 看个人中心 → 看记录

```
打开小程序
  → 已有登录态，直接进入
  → 底部「我的」
  → 个人中心：头像/昵称、通关/星星/连续天、累计积分、今日额度
  → 点「学习记录」→ 记录列表（时间倒序）
  → 点「设置」→ 资料/隐私/退出登录/注销
```

### 3.3 换设备

```
新手机打开 → 「我的」→ 微信登录
  → 同一微信 → 同一账号
  → 学习记录、积分、额度全部可见
```

### 3.4 异常旅程

| 场景 | 期望 |
| --- | --- |
| 用户取消微信授权 | 留在当前页，提示“已取消登录，可稍后再试”，不丢输入 |
| 微信登录配置缺失/网络失败 | 明确提示原因 + 重试；不出现白屏或死循环 |
| 登录态过期 | 需要造关时提示重新登录；浏览与已有报告不强制打断 |
| 额度用完 | 显示“今日 3/3 已用完，明天 00:00 恢复”，不隐藏入口、不制造焦虑 |
| 游客记录迁移失败 | 告知“记录稍后同步”，不能假装成功；重试幂等 |

## 4. 需求批次与优先级

> 优先级：**P0 本期必须**；**P1 本期应做（体验/合规）**；**P2 后续版本**。
> 批次按“先登录、再资料/个人中心、最后设置/合规”的顺序交付，每批可独立验收。

| 批次 | 优先级 | 主题 | 包含需求 | 交付后能演示什么 | 依赖 |
| --- | --- | --- | --- | --- | --- |
| **批次 1** | P0 | 账号与门禁 | FR-01 微信登录/自动注册、FR-02 登录态/退出、FR-03 体验登录、FR-04 游客试用/登录门禁、FR-05 配额、FR-06 数据迁移 | 游客试 1 组 → 登录 → 继续造关；同一微信再次登录还是同一账号 | 微信 AppID/AppSecret（真实登录）；体验登录兜底 |
| **批次 2** | P0 | 资料、个人中心、积分、记录 | FR-07 昵称/头像、FR-08 个人中心 S11、FR-09 积分、FR-10 学习记录列表 | “我的”页完整可用；能看到累计积分与历史记录；换设备可见 | 批次 1 |
| **批次 3** | P1 | 设置、隐私、账号生命周期 | FR-11 设置页、FR-12 学习提醒偏好、FR-13 隐私同意/协议、FR-14 注销账号、FR-15 异常与风控、FR-16 兼容与回归 | 设置/隐私/退出/注销完整；异常态可恢复 | 批次 1、2 |
| **后续** | P2 | 成长与传播 | S09 错题本、S10 成就与段位、S12 分享、S13 排行榜、VIP/支付 | 本期不做 | 本期账号体系 |

### 4.1 为什么这样排

1. **登录是地基**：没有账号，个人中心/记录/额度都无法按人计算；先做批次 1，后续所有页面才有数据归属。
2. **资料与个人中心是用户可感知的价值**：登录后如果看不到“我是谁、我学了多少”，登录就没有意义；所以批次 2 紧跟。
3. **设置与合规是上线门槛**：隐私同意、注销、退出可以晚于主链路，但不能缺席；放批次 3。
4. **S09–S13 是留存增强，不是账号前提**：本期先把“账号 + 个人中心 + 配额”做扎实，避免范围蔓延。

## 5. 功能需求

> 编号规则：`FR-xx`。每条包含目标、规则、状态与验收口径。验收统一用“给定/当/则”（Given/When/Then）。

### FR-01 微信登录与自动注册（P0 · 批次 1）

| 项 | 内容 |
| --- | --- |
| 目标 | 用户用微信身份进入产品；首次登录自动创建账号，不额外填写注册表单 |
| 触发 | 游客点击“登录”、造关额度用完、个人中心登录 CTA、设置页登录 |
| 主流程 | 用户点击登录 → 拉起微信授权 → 获得微信登录凭证 → 服务端换取微信唯一标识 → 首次则创建账号，非首次则登录原账号 → 返回登录态与用户资料 |
| 账号规则 | 同一微信唯一标识 = 同一账号；不同微信 = 不同账号；不提供手机号/邮箱/密码注册 |
| 资料规则 | 首次登录默认昵称为“旅人”，默认头像为墨团；登录后引导补充昵称/头像（FR-07），可跳过 |
| 失败处理 | 用户取消、网络失败、凭证过期、服务端未配置微信登录：均给出中文可读提示与“重试”；不丢当前页面输入 |
| 安全边界 | 不在客户端保存微信密钥；不获取手机号、通讯录、好友列表、真实姓名 |
| 验收 | 给定新微信，当首次登录，则创建账号并进入个人中心；给定同一微信再次登录，则进入同一账号且记录一致；给定用户取消授权，则停留在原页并可重试；给定未配置微信登录，则提示“微信登录暂不可用”而不是报 500 |

**已确认（默认）**：本期“注册”即首次微信登录自动建号，不另做注册页。

### FR-02 登录态与退出（P0 · 批次 1）

| 项 | 内容 |
| --- | --- |
| 目标 | 登录后无需反复登录；退出后立即失效；数据不丢 |
| 登录态 | 登录态跨小程序重启保持；有效期至少 30 天；过期或服务端判定失效时要求重新登录 |
| 退出 | 设置页/个人中心提供“退出登录”；二次确认；退出后清除本机登录态；服务端学习记录保留 |
| 失效处理 | 需要登录的操作提示“登录已过期，请重新登录”；浏览/已有报告不被强制打断 |
| 验收 | 给定登录后关闭再打开，则仍为登录态；给定退出，则“我的”显示游客态且造关需重新登录；给定退出后重新登录，则历史记录/积分恢复；给定登录态过期，则提示重新登录且不丢当前输入 |

### FR-03 体验登录（仅开发/测试，P0 · 批次 1）

| 项 | 内容 |
| --- | --- |
| 目标 | 在 H5、本地联调、自动化测试中不依赖真实微信也能验证登录后全流程 |
| 规则 | 仅在非生产环境可用；生产环境必须不可见、不可调用；体验账号与真实微信账号可区分；不产生真实微信绑定 |
| 入口 | 登录弹层/登录页在开发环境显示“体验登录”；生产包不显示 |
| 验收 | 给定开发环境，当点击体验登录，则创建/进入体验账号并可完成造关；给定生产环境，则看不到入口且直接调用被拒绝 |

### FR-04 游客试用与登录门禁（P0 · 批次 1）

| 项 | 内容 |
| --- | --- |
| 目标 | 降低首次门槛，同时把无限白嫖收敛为“1 组试用 + 登录后 3 组/日” |
| 游客可用 | 浏览首页、章节地图、已有报告；可完成 1 组 AI 造关（含答题/结算/报告） |
| 游客不可用 | 第 2 组起的 AI 造关；修改昵称/头像；查看账号级学习记录/设置 |
| 登录门禁时机 | 点击“生成关卡”时判断；不登录不阻断浏览与已生成内容 |
| 登录后续接 | 登录成功后自动回到原输入页，保留主题/难度/题量/题型，用户再点一次即可生成；或自动继续（二选一，建议保留用户确认，避免误扣额度） |
| 额度口径 | 游客试用为**累计 1 组**（非每日重置）；该组不占用登录后的每日额度 |
| 提示文案 | “已体验 1 组。登录后可继续造关，学习记录也会跟着账号走。” |
| 验收 | 给定游客第 1 次造关，则允许；给定游客第 2 次造关，则弹登录且不创建会话；给定登录成功，则原输入仍在；给定游客不登录，则浏览/查看已有报告不受影响 |

**已确认（默认）**：游客 1 组为每设备累计 1 组。

### FR-05 AI 造关配额（P0 · 批次 1）

| 项 | 内容 |
| --- | --- |
| 目标 | 控成本、防滥用，同时规则对用户透明 |
| 游客 | 累计 1 组试用；用完后必须登录 |
| 登录普通用户 | 3 组/日；每日 00:00（Asia/Shanghai）重置 |
| VIP | 10 组/日，**本期不开放**；仅保留规则位，不提供购买/兑换入口 |
| 计数对象 | 一次 AI 造关 = 1 组；普通造关、每日挑战、章末综合均计 1 组 |
| 不计数 | 生成失败后的“重试”；预览页“重新生成”；未来错题重练（复用已有题目） |
| 超限 | 不隐藏造关入口；点击后提示“今日 3/3 已用完，明天 00:00 恢复”；不启动生成、不扣额度 |
| 展示 | 个人中心额度卡展示“今日已用 X / 3”；游客展示“试用 0/1”；VIP 未开放时不展示 VIP 字样 |
| 失败返还 | 创建成功即计 1 组；同一次造关失败重试不重复计；整组最终失败返还额度 |

| --- | --- | --- | --- | --- |
| 微信唯一标识 | 是 | 账号识别、跨端同步 | 账号存续期 | 不展示给用户 |
| 昵称 | 是（可跳过） | 个人中心、记录列表 | 账号存续期 | 默认“旅人” |
| 头像 | 是（可跳过） | 个人中心 | 账号存续期 | 默认墨团；≤2MB |
| 学习记录 | 是 | 学习记录列表、积分、报告 | 账号存续期 | 含主题、答案、得分等 |
| 积分 | 是 | 个人中心、段位 | 账号存续期 | 由学习记录汇总 |
| 额度使用 | 是 | 配额控制 | 至少 90 天 | 游客试用标记 |
| 设备标识 | 是 | 游客隔离、风控 | 90 天 | 非 PII |
| 登录日志 | 是 | 安全风控 | 90 天 | 时间/结果/IP，最小化 |
| 手机号 | 否 | — | — | 不收集 |
| 通讯录/好友 | 否 | — | — | 不收集 |
| 真实姓名/身份证 | 否 | — | — | 不收集 |
| 精确位置 | 否 | — | — | 不收集 |

### 7.2 隐私要求

1. 首次登录前必须明示同意《用户协议》《隐私政策》，默认不勾选。
2. 用户可在设置中查看协议、退出登录、注销账号。
3. 不使用用户学习数据训练模型；不向第三方出售/共享（法律法规要求除外）。
4. 日志不记录完整答案、微信密钥、登录凭证。
5. 注销后按 FR-14 删除/匿名化，并在隐私政策中写明时限。
6. AI 生成内容始终带“内容由 AI 生成，仅供学习参考”标识。

### 7.3 数据一致性要求

- 个人中心积分 = 该账号已完成学习记录的积分之和。
- 记录列表条数 = 该账号可见的学习记录数（分页总数一致）。
- 额度卡数字 = 服务端实际可用额度；前端不得自行估算。
- 登录后游客记录迁移不重复、不丢失。
- 退出后游客态不显示账号数据。
