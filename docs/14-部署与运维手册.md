## 2. 本地启动

```bash
# 后端（先启动本地独立 MySQL 3307）
cd backend
./scripts/start_mysql_dev.sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # MYSQL_PORT=3307, MYSQL_DATABASE=lwa_dev
.venv/bin/uvicorn app.main:app --reload --port 8000

# 前端
cd miniapp
npm install
npm run build:weapp       # dist/
npm run build:h5          # dist-h5/
python3 scripts/serve_h5.py dist-h5 10087
```

- API 文档：`http://127.0.0.1:8000/docs`
- 健康检查：`/api/v1/health`（当前本地应返回 `database=mysql`、`wechat_login=true`、`dev_login=true`）
- 小程序：微信开发者工具导入 `miniapp/`，本地勾选“不校验合法域名”。

## 3. 环境变量

`backend/.env`（本地）/ 进程环境变量（生产）。完整示例见 `backend/.env.example`（可提交/开源，不含真实密钥；复制后填写 `WECHAT_APP_ID` / `WECHAT_APP_SECRET` 等）。模板校验：`python3 scripts/check_env_example.py`。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_VERSION` | `0.3.0` | `/health` 与 OpenAPI 版本 |
| `ENV` | `dev` | `dev/test/production`；production 关闭体验登录 |
| `ENV` | `dev` | 环境标识 |
| `LLM_PROVIDER` | `auto` | auto/deepseek/mock |
| `DEEPSEEK_API_KEY` | 空 | 为空则 Mock |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容；第三方网关写到 `/compatible-mode/v1` |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 可切 `deepseek-v4-pro` |
| `DEEPSEEK_THINKING` | `false` | 是否开启思考模式 |
| `DEEPSEEK_TIMEOUT` | `120` | 秒 |
| `DEEPSEEK_MAX_RETRIES` | `2` | SDK 重试 |
| `ENABLE_WEB_SEARCH` | `true` | 真实模式是否检索；第三方网关通常无 Search API，设 false |
| `DEEPSEEK_SEARCH_BASE_URL` | `https://api.deepseek.com` | Search API 独立 Base URL |
| `SEARCH_COUNT` | `6` | 来源上限 |
| `MYSQL_HOST` | `127.0.0.1` | MySQL 主机 |
| `MYSQL_PORT` | `3306` | 端口；本地独立实例用 3307 |
| `MYSQL_USER` / `MYSQL_PASSWORD` | `lwa` / 空 | 最小权限账号 |
| `MYSQL_DATABASE` | `lwa_dev` | 库名（utf8mb4） |
| `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 空（模板） | 真实微信登录；当前本地 `.env` 已填写并加载（health.wechat_login=true）；模板保持空值 |
| `DEV_LOGIN_ENABLED` | `true` | 仅非生产可用；生产必须 false |
| `AUTH_TOKEN_TTL_DAYS` | `30` | 登录态有效期 |
| `QUOTA_ENFORCED` | `true` | 是否强制配额；测试可 false |
| `GUEST_TRIAL_LIMIT` | `1` | 游客累计试用组数 |
| `DAILY_QUOTA_USER` | `3` | 登录用户每日组数 |
| `VIP_DAILY_QUOTA` / `VIP_ENABLED` | 10 / false | VIP 预留，本期不开放 |
| `LOGIN_RATE_LIMIT_PER_HOUR` | `20` | 每 IP 登录尝试 |
| `AVATAR_UPLOAD_DIR` / `AVATAR_MAX_BYTES` | `./data/uploads/avatars` / 2MB | 头像存储 |
| `MAX_SESSION_AGE_DAYS` | `7` | 配置存在，清理任务未实现 |
| `MAX_TOPIC_CHARS` | `200` | 主题上限 |
| `MIN_QUESTION_COUNT` / `MAX_QUESTION_COUNT` | 3 / 10 | 题量 |
| `RATE_LIMIT_PER_HOUR` | `30` | 每 IP 每小时创建 |
| `CORS_ORIGINS` | `*` | 生产收敛到 H5 域名 |
| `COST_INPUT_PER_M` / `COST_OUTPUT_PER_M` | 2 / 8 | 成本估算（元/百万 token） |

**安全**：不要把 Key 写入镜像、代码、前端或日志；生产用 Secret/环境变量注入；定期轮换。

## 4. Docker 最小示例

`backend/Dockerfile`（当前未提交，可按需添加）：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY backend/app ./app
RUN mkdir -p /app/data
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "1"]
```

> MySQL 连接数与 worker 需匹配；低配实例先用 `--workers 1–2`，并配置连接池/超时。

`docker-compose.yml`：

```yaml
services:
  api:
    build:
      context: .
      dockerfile: backend/Dockerfile
    env_file: backend/.env
    volumes:
      - ./backend/data:/app/data
    ports:
      - "127.0.0.1:8000:8000"
    restart: unless-stopped
```

## 5. Nginx + HTTPS

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    client_max_body_size 1m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 180s;   # 覆盖模型最长耗时
    }
}
```

- 证书：Let's Encrypt（certbot）自动续期。
- 只开 443；80 跳转 443；后端只监听 127.0.0.1。
- 微信小程序 request 合法域名必须是 **HTTPS、已备案、无端口**。

## 6. 微信小程序发布

1. `miniapp/project.config.json` 填真实 AppID（当前 `touristappid` 占位）。
2. `TARO_APP_API_BASE=https://api.example.com npm run build:weapp`。
3. 开发者工具导入 `miniapp/` → 上传体验版 → 真机验收。
4. 公众平台配置 request 合法域名；勾选业务域名（如 H5）。
5. 类目：工具→效率 或 教育→教育工具；避免 K12 学科培训。
6. AI 生成标识、隐私政策、用户协议、免责声明。
7. 提审 → 发布。

**H5**：`dist-h5/` 静态托管；需要 SPA fallback（hash 路由下不强制，但建议）。若切 browser 路由，Nginx 加 `try_files $uri $uri/ /index.html;`。

## 7. 数据库运维

```bash
# 在线备份（MySQL）
mysqldump --single-transaction --routines --triggers \
  -h 127.0.0.1 -P 3306 -u lwa -p lwa_dev > backup-$(date +%F).sql

# 恢复（停服务后）
systemctl stop learning-with-ai
mysql -h 127.0.0.1 -P 3306 -u lwa -p lwa_dev < backup-YYYY-MM-DD.sql
systemctl start learning-with-ai
```

- 每日备份 + 保留 7 天；备份文件不要入库。
- 监控 MySQL 连接数/慢查询/锁等待；连接池与 `--workers` 按实例规格调整。
- 头像文件目录 `backend/data/uploads/avatars` 需纳入备份或对象存储。
- 迁移：启动时 `init_db()` 自动 `ALTER TABLE ADD COLUMN`；**只加列不删列**。重大变更先在 staging 副本演练。
- 清理任务（未实现）：按 `MAX_SESSION_AGE_DAYS` 删除匿名会话；报告 30 天；答案 30 天。

## 8. 监控与告警（建议）

| 指标 | 采集 | 阈值 |
| --- | --- | --- |
| ready 率 | 日志 `status=ready` / 创建数 | <95% 告警 |
| 生成 P90 | stage 时间差 | >45s |
| LLMError 率 | 日志/异常计数 | >5% |
| 报告生成率 | completed / ready | 异常下跌 |
| 单组成本 | `sessions.cost_cny` 汇总 | 日均 > 预算 120% |
| 5xx | 访问日志 | >1% |
| `database is locked` | 日志 | 连续出现 |

当前实现：Python logging（`%(asctime)s %(levelname)s [%(name)s] %(message)s`），没有结构化 JSON/Sentry/Prometheus。M4 前补齐。

## 9. 发布与回滚

1. `CHANGELOG.md` 版本号。
2. 回归：`pytest` + `tsc` + 双端构建 + E2E + 真机关键页。
3. 镜像 tag：`api:0.2.0`。
4. 灰度 10% → 观察 30 分钟 → 全量。
5. 回滚：`docker compose up -d --no-deps api:<prev>`；数据库变更必须向后兼容。
6. 发布后 24h：错误率、ready 率、P90、成本、报告打开率。

## 10. 安全检查清单

- [ ] `backend/.env` 不在镜像/仓库；Key 只存 Secret。
- [ ] CORS 收敛到具体 H5 域名（生产不要 `*`）。
- [ ] HTTPS 全链路；禁 HTTP。
- [ ] 微信 request 合法域名配置完成。
- [ ] 限流阈值按真实流量调整；多实例改 Redis。
- [ ] `session_id` 不可枚举（12 hex ≈ 2.8e14）；M4 加 openid/HMAC。
- [ ] 日志不记录完整用户答案/Key。
- [ ] 备份可用、恢复演练过。
- [ ] 内容审核（`msgSecCheck`）与 AI 标识上线。
- [ ] 隐私政策、用户协议、免责声明可访问。
- [ ] 类目/备案/生成式 AI 登记确认。

## 11. 运行手册（Runbook）

| 场景 | 操作 |
| --- | --- |
| 生成一直 queued | 看后端日志/BackgroundTasks 异常；检查 Key/网络；失败会写 `error` |
| 401/402 | 换 Key/充值；重启后端 |
| 报告 409 | 等 `completed` 再取；前端已先轮询 |
| MySQL 锁等待 | 查 `SHOW PROCESSLIST`/慢查询；降并发、加索引 |
| 磁盘满 | 清理备份/日志；检查 binlog 与数据目录 |
| 误删数据 | 停服务 → 用最近备份恢复 → 校验 |
| Key 泄露 | 立即吊销 → 换 Key → 查账单 → 记录事故 |

更多症状见 [15-故障排查与FAQ](./15-故障排查与FAQ.md)。
