## 4. 已知限制与风险

| ID | 问题 | 影响 | 临时方案 |
| --- | --- | --- | --- |
| K-01 | 无登录，session_id 即凭证 | 换设备不同步；理论可猜解 | M4 登录 + HMAC |
| K-02 | 限流在进程内存 | 多实例失效 | 单实例部署；P1 Redis |
| K-03 | SQLite 单写 | 高并发 `database is locked` | WAL + 短事务；M4 迁 PG |
| K-04 | Mock 数据固定 | 不能代表真实质量 | 真实 Key 联调 + 评测集 |
| K-05 | 报告 LLM 失败会降级为规则文案 | 个性化下降 | 可接受；监控失败率 |
| K-06 | 小程序字体依赖系统回退 | 不同机型字形差异 | 子集字体（P1） |
| K-07 | H5 分享图未实现 | 无法传播 | P1 Canvas 合成 |
| K-08 | 无内容审核 | 合规风险 | 上线前必须补 |

## 5. 复现步骤

```bash
# 后端
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
LLM_PROVIDER=mock .venv/bin/uvicorn app.main:app --port 8000

# 前端构建
cd ../miniapp
npm install
npm run build:weapp
npm run build:h5

# H5 E2E（另开终端）
python3 scripts/serve_h5.py dist-h5 10087
node scripts/e2e.js
```

> 真实模式：在 `backend/.env` 填 `DEEPSEEK_API_KEY`，设 `LLM_PROVIDER=deepseek`，重启后重复 E2E，记录耗时、token 与成本。
