## 2. 按角色阅读

**产品 / 设计**
`01 需求规格` → `03 页面设计说明` → `02 UI 设计规范` → `prototype/` 两个 HTML → `04 ADR`（了解取舍）

**前端开发**
`02 UI 设计规范`（令牌与组件）→ `03 页面设计说明`（状态与数据）→ `方案设计文档` 第 6 章（接口）→ `05 测试报告`（验收方式）

**后端开发**
`方案设计文档` 第 3～7 章 → `01 需求规格` 的 FR/NFR → `04 ADR` → `05 测试报告`

**评审 / 接手**
`docs/README`（本页）→ `01 需求规格` 第 1～4 章 → `04 ADR` → `05 测试报告` → `CHANGELOG`

## 3. 职责边界（避免同一件事写在四个地方）

| 问题 | 唯一负责文档 | 其他文档只做引用 |
| --- | --- | --- |
| 需求范围、优先级、验收标准 | `01-需求规格说明书` | 页面说明引用 FR 编号 |
| 技术选型、架构、接口、数据模型 | `方案设计文档` | 页面说明引用接口路径 |
| 颜色、字体、组件、动效、无障碍 | `02-UI设计规范` | 页面说明引用组件名 |
| 每个页面的布局、状态、文案、数据 | `03-页面设计说明` | 原型 HTML 是它的可视化版本 |
| 关键决策的原因与代价 | `04-ADR决策记录` | 其他文档可链接 ADR 编号 |
| 当前质量状况与已知缺口 | `05-测试与验收报告` | README 只给结论 |
| 流程、分支、发布、文档维护 | `06-协作与发布指南` | — |

**冲突处理**：需求与页面说明冲突 → 以需求规格为准；视觉与实现冲突 → 以 UI 规范为准；任何一方要改，必须同步改 ADR 并记录原因。

## 4. 版本与维护

| 规则 | 说明 |
| --- | --- |
| 版本号 | `v主.次`；主版本=范围/结构变化，次版本=补充与修正 |
| 更新触发 | 需求变更、UI 评审、接口变化、发布、重大缺陷复盘 |
| 评审 | 需求与 UI 需产品/设计确认；接口与数据需后端确认；发布需至少一人按检查清单过一遍 |
| 归档 | 过期内容不删除，移到"历史决策"并注明失效日期与替代文档 |
| 同步 | 代码 PR 涉及行为变化时，必须同时更新 `03` 或 `05`，否则不合入 |
